# Webアプリ品質チェックリスト & 知見リファレンス

本スキルは、過去の不具合（片肺機能、UIとロジックの未結合、高校理科分類の混入、UTCタイムゾーンずれ、無効UI導線）を再発させないための実装前・実装後チェックリストです。

詳細な事故事例と再発防止策は [junior-vet-exam-chart/docs/LESSONS_LEARNED.md](../../junior-vet-exam-chart/docs/LESSONS_LEARNED.md) に記載されています。

---

## チェック項目

### 1. UIとロジックの完全結合
- [ ] ボタンを押した際、単に視覚が変わるだけでなく、実際のデータ（localStorage / IndexedDB）が更新・永続化されているか？
- [ ] 画面を再読み込み（リロード）しても、更新したデータが維持されているか？
- [ ] データ定義（動物の鳴き声、豆知識など）が画面の演出に100%反映されているか？

### 2. 双方向性の保証（エクスポート ⇆ インポート）
- [ ] データをファイル出力（書き出し）できる場合、そのファイルを読み込んで元の状態に完全復元できるインポートUIと処理があるか？
- [ ] バックアップ対象に、IndexedDBの全テーブルだけでなくlocalStorageの設定・進度も含まれているか？

### 3. 対象ユーザー（小学生）目線の用語統制
- [ ] 「生物・物理・地学・化学」などの高校理科分類が混入していないか？（「🧪 理科」「📐 算数」「🗾 社会」に統一されているか？）
- [ ] 機能名（「合格ドクター認定試験」等）が画面全体で統一されているか？
- [ ] カギやバッジなどのゲーム要素について、「どうやって集めるか」「集めたら何が起きるか」の説明が明記されているか？

### 4. タイムゾーン（JST: 日本標準時）の厳密性
- [ ] GitHub Actions（Ubuntu）はUTCである前提で、`Intl.DateTimeFormat` に `timeZone: 'Asia/Tokyo'` を指定しているか？
- [ ] バックアップ等のダウンロードファイル名の日付が日本時間の日付になっているか？

### 5. 原本忠実性と設問間の答え漏洩（ネタバレ）防止
- [ ] 原本が存在する問題は、原本の表記・語句を勝手にアレンジ・肉付け・補足をせず完全忠実に文字起こししているか？
- [ ] 単問化の都合などで親切心の補足括弧（例: `組織㋒（師管）`、`問5の構造（根毛）`）が問題文（prompt）に混入していないか？
- [ ] 同一セクション内で先行する設問の正解語句（term）が、後続設問の問題文で漏洩していないか？（`prompt-leakage.test.ts` が通過しているか？）

### 6. 問題用紙と解答用紙の完全一致
- [ ] 問題用紙の各設問（記述・選択・語句）と解答用紙のスロット（`slots`）の設問番号・小問ラベル・answerType（`open` / `choice` / `term` / `numeric`）が1対1で整合しているか？
- [ ] 記述説明問題に対して架空の小問（「植物A」「植物B」等）や選択式入力欄が表示されていないか？
- [ ] テスト失敗時にテスト側のアサーション（例: 22欄→23欄）を安易に書き換えていないか？

### 7. Stage 2（同等未見問題）における選択肢の提示保証とネタバレ防止
- [ ] 選択問題（`choice` / `multi_choice`）において、問題用紙エリアに選択肢カード（ア〜エのテキスト）が正しく描画されているか？
- [ ] 問題文（`stage2Prompt`）の中に答えとなる用語（例: `（二酸化炭素）` `（函館）` `（20℃以下）` 等）が括弧書き等で混入・漏洩していないか？
- [ ] `prompt-leakage.test.ts` で全教科の Stage 2 設問のネタバレ不在と選択肢の存在が保証されているか？

### 8. 合格のカギと認定試験二段階報酬の分離・連動
- [ ] 「合格のカギ」がカルテ領域（左カラム）に配置され、テーマの【⭐Lv.4 マスター】獲得と正しく連動しているか？
- [ ] カギを全問集めたときに「🐾 全動物たちからの特別感謝メッセージ」モーダルがアンロックされるか？
- [ ] 認定試験のクリア報酬が段階的に分離されているか？
  - Stage 1 クリア: 👑「合格ドクター認定証（ライセンス）」授与＆画像保存
  - Stage 1 & 2 両方クリア: ⭐「金のマスター獣医師バッジ」アンロック
- [ ] 認定証モーダルや成績表モーダルで、Stage 1 & 2 制覇時のみマスターバッジが有効化されるか？

### 9. PWAアプリアイコンとマニフェスト完全性
- [ ] `public/` 直下に、192x192、512x512、maskable 512x512、apple-touch-icon 180x180 の実体PNG画像が存在しているか？
- [ ] `vite.config.ts` の manifest icons に `purpose: "any"` および `purpose: "maskable"` が正しく設定されているか？
- [ ] Android タブレット・スマホでのホーム画面追加時に、適応型アプリアイコンが欠けずに表示されるか？

### 10. 無効なリソース・UIの非表示
- [ ] 画像やスキャン原本が存在しないモード（Stage 2など）で、不要な切り替えボタンが表示されていないか？

### 11. 画面遷移と戻る導線の一貫性保証（ヤコブの法則）
- [ ] 学習完了画面を含む全画面において、画面左上に常時「戻る」ボタン（`←`）が配置されているか？
- [ ] 学習完了画面など次のアクションを促すCTAがある画面は、左上と最下部のハイブリッド配置になっているか？

### 12. アフォーダンスの明確性と固定ダミー数値の根絶
- [ ] 押せる要素（ボタン）と押せない要素（情報ラベル）が見た目から直感的に判別できるか？ ピル型デザインが乱用されていないか？
- [ ] 科目フィルターなどの状態切り替えにトレイ型セグメントコントロールが使われているか？
- [ ] タイマーが存在しない機能に「30秒」等の具体的時間を冠していないか？
- [ ] 「35%」「3日」のような固定ダミー値がコードにベタ書きされておらず、記憶定着度やセッション履歴から完全動的計算されているか？

### 13. A4弱点克服チェックシート印刷の専用レイアウト保証
- [ ] 印刷ボタンを押した際、Web画面やモーダル枠、背景が消え、A4縦1枚に収まる専用ワークシートのみが印刷対象となるか？（`@media print`）
- [ ] 机での紙と鉛筆の学習用に、急所ポイント・設問・計算メモ枠・解答欄・天地逆の答え合わせ欄が整然とレイアウトされているか？

### 14. 保護者向け画面のペルソナ整合と本日の学習量優先表示
- [ ] 保護者カルテで保護者に問題を解かせるチグハグなUIになっていないか？（「急所・指導ヒントを見る」として家庭での声かけのコツや正解を提示しているか？）
- [ ] サブ操作（暗記カード起動など）を行って閉じても、親モーダル（保護者カルテ）が開いたまま維持されるか？
- [ ] 保護者が最も知りたい「本日の学習時間」「本日の解答数」が最優先で確認できるサマリーレイアウトになっているか？

### 15. 学習・試験画面の操作ボタン整理と誤操作防止（戻る導線の安全化）
- [ ] 学習画面に「やめる」等の不要な離脱ボタンを置かず、左上「←」戻るボタン時も安全な中断確認モーダルが開くか？
- [ ] 中断モーダルで「学習をつづける」「ここまでの記録を残してホームへ（セーブ中断）」「最初からやり直す（リセット）」の2大ユースケースが明快に選べるか？

### 16. 結果が予測できる具体的ボタン表現（アフォーダンスの徹底）
- [ ] 「分かった」などの押した後に何が起きるか不明瞭なボタンを排除し、「今すぐ選択肢を見る ❯」のように結果が即座に理解できる具体的ラベルになっているか？

### 17. レスポンシブ幅におけるピル型変形の根絶と文字縦割れ防止
- [ ] バッジ、タグ、ボタンに `white-space: nowrap` と `flex-shrink: 0` が付与され、画面幅縮小時に文字が縦1文字ずつ改行されて卵型に変形しないか？
- [ ] 画面サイズに応じた自然な角丸（PC: 8px / モバイル: 6px）と `flex-wrap: wrap` を適用し、画面外への見切れをゼロにしているか？

### 18. 大量リスト表示における縦スクロール爆発の防止
- [ ] カルテ進度などのテーマ数が多いリスト領域はデフォルトで折りたたまれ（閉）、縦スクロールが爆発せず認定試験等の重要下部コンテンツへ最短でアクセスできるか？

### 19. 全フォーム要素への一意な id・name 属性の付与
- [ ] すべての input, textarea, select に一意な `id` および `name` 属性が付与され、label と正しく紐付いているか（ブラウザ警告0件）？

### 20. CI/CDデプロイパイプラインの競合防止とPWA安全フォールバック
- [ ] GitHub Pages 設定の Source は「GitHub Actions」に統一され、組み込みワークフロー（`pages build and deployment`）との二重起動・環境ロックを防止しているか？
- [ ] サーバー上の `version.json` 取得が404やオフライン等で失敗しても、アプリ全体をクラッシュさせず通常学習を継続できる安全フォールバックが徹底されているか？

### 21. バージョン管理とリリース
- [ ] `package.json` のバージョンを引き上げたか？
- [ ] Git注釈付きタグ（`git tag -a vX.Y.Z -m "..."`）を作成し、リモートへプッシュしたか？
- [ ] 設定画面からキャッシュを完全パージして強制リロードできるか？
