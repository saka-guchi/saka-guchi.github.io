# みならい獣医さんの中学受験カルテ - 開発知見集（Lessons Learned）

本ドキュメントは、開発・運用中に発生した不具合の根本原因と再発防止策をまとめた知見集です。
今後の機能追加・改修時における品質担保の指針として参照してください。

---

## 1. 発生した不具合と根本原因（Root Cause Analysis）

### ① 片肺機能（エクスポートのみでインポート未実装）
* **事象**: 「学習履歴のバックアップ」でJSONを書き出せるが、取り込むUIもロジックも存在しなかった。
* **原因**: 出力（エクスポート）機能の実装だけで満足し、入力（インポート・復元）およびその用途（端末移行やキャッシュクリア前の退避）の説明が抜け落ちていた。
* **再発防止策**:
  * データの「書き出し」を作る際は、必ず「取り込み（復元）」とセットで設計・実装する。
  * バックアップ対象には、IndexedDBだけでなくlocalStorage（記憶メーター、動物シール等）も漏れなく含める。

### ② UIとロジックの未結合（ダミー表示）
* **事象**:
  * 30秒暗記カードで「思い出せた！」を押しても記憶メーターが動かない。
  * 動物シール帳に「クリックすると鳴き声や豆知識が飛び出す」とあるのに、最初から豆知識が見えており、鳴き声（`cheerMessage`）が使われていなかった。
* **原因**:
  * UI側で「押したときのイベント」は発火していたが、数値を更新・保存・同期する裏側のロジックが未接続だった。
  * データ定義に用意したプロパティ（`cheerMessage`）を画面のインタラクションと結合していなかった。
* **再発防止策**:
  * ボタンやタップ可能な要素を配置したら、「押下で何が変わり、どこに保存され、どう視覚変化するか」をテストコード（Vitest / RTL）で必ず検証する。

### ③ ユーザー目線に合わない用語・分類の露出
* **事象**:
  * 小学生向けアプリなのに、分類タブが高校理科の「生物・物理・地学・化学」になっていた。
  * 「合格ドクター認定試験」「過去問原本スキャンでの本番模試」「本番認定試験」など、同じ機能に対して呼称が揺れていた。
  * 「カギのかけら」をどうやって集めるのか、集めたら何が起きるのかの説明がなかった。
* **原因**: 開発内部のデータ構造やモデル名をそのままUIに出力してしまい、児童が迷わず楽しく進められるUI導線・ストーリー性の配慮が不足していた。
* **再発防止策**:
  * 分類は小学生が親しみやすい「🧪 理科」「📐 算数」「🗾 社会」の教科別を基本とする。
  * 機能名称は正式名称（例: 「合格ドクター認定試験」）に統一する。
  * ゲーム要素（カギ・スタンプ等）は、「獲得条件（例: ⭐Lv.4達成でGET）」と「集めた後の特典」を必ず明記する。

### ④ CI環境（UTC）と日本標準時（JST）のズレ
* **事象**: 夜（21時台）にデプロイしたのに、画面のビルド日時が「12時（昼）」と表示された。
* **原因**: GitHub Actions（Ubuntu runner）のシステムタイムゾーンがUTC（世界標準時）であるため、タイムゾーン指定なしでフォーマットすると JST から -9時間 ズレてしまう。
* **再発防止策**:
  * ビルドスクリプト（`vite.config.ts`）や日付フォーマットでは、常に `timeZone: 'Asia/Tokyo'`（`Intl.DateTimeFormat`）を明示的に指定する。
  * CI環境（`.github/workflows/deploy.yml`）にも `TZ: 'Asia/Tokyo'` を設定する。
  * ファイル名（`junior-vet-backup-YYYY-MM-DD.json`）も JST 基準で生成する。

### ⑤ 原本スキャン等、無効なUI導線の残存
* **事象**: Stage 2（同等未見テスト）で原本スキャンの切り替えボタンが押せるが、原本が存在しないため何も起きない。
* **原因**: コンポーネントが原本画像の有無やステージを意識せず、ボタンを無条件にレンダリングしていた。
* **再発防止策**:
  * リソースが存在しない状態では、無効なボタンを非表示（または disabled）にする。

### ⑥ バージョン管理とキャッシュ対策
* **事象**: デプロイしてもPWA/ブラウザのキャッシュによって古いコードが実行され、白画面や不具合が継続する。また、Gitタグによる履歴管理がされていなかった。
* **再発防止策**:
  * 設定画面にバージョン・ビルド日時を明記し、ワンタップでService WorkerとCacheStorageを全削除してリロードできる仕組みを提供する。
  * リリース時には `package.json` のバージョンを引き上げると同時に、Git注釈付きタグ（`git tag -a vX.Y.Z -m "..."`）を作成してプッシュする。

### ⑦ タイマーの独立保持とタイムアップ仕様（未定義UIの根絶）
* **事象**:
  * 認定試験で科目を行き来すると残り時間が初期値にリセットされて復活してしまう。
  * 残り時間が 0:00 になっても何も起きず放置され、時間切れで何が起きるのかの説明も一切なかった。
* **原因**:
  * 各教科ごとの残り時間を別々に管理せず単一の state を科目切り替え時に初期化していた。
  * タイマー終了時のコールバックやタイムアップモーダルが実装されておらず、ルールの画面案内も欠落していた。
* **再発防止策**:
  * 複数対象（科目・ステージ）の制限時間は個別に独立した state で経過時間を維持する。
  * 残り時間ゼロ（0:00）時は自動で提出・採点へ進むフロー（タイムアップ通知モーダル経由）を必ず結合する。
  * タイマーおよび解答欄付近に「0:00で自動提出・採点」等のルール案内を明記する。

### ⑧ UI表現の混在（ブラウザalertの残存）と採点カルテ履歴の永続化
* **事象**:
  * 全画面・アプリ内モーダル・ブラウザネイティブの `alert(...)` が混在し、ポリシーが不透明だった。
  * 認定試験で不合格になった際、ブラウザの `alert()` で通知され、OKを押すと強制的に画面が消えてしまい、保護者に採点結果を見せたり過去の履歴を振り返ることができなかった。
* **原因**:
  * 開発時の仮実装 `alert(...)` を放置し、UI表現の統一ポリシー（全画面＝集中学習／モーダル＝補助操作／alert＝完全禁止）が定義されていなかった。
  * 採点結果データをIndexedDBに保存していながら、過去履歴を一覧・再確認するUIが提供されていなかった。
* **再発防止策**:
  * ブラウザネイティブの `alert()` / `confirm()` は完全禁止（コード内 0件）とし、すべて世界観に合わせたアプリ内リザルトモーダルで結果発表を行う。
  * 過去の全受験履歴（日時JST、各教科の得点、合否、合格回の認定証再表示）を閲覧できる成績表カルテUI（`FinalExamHistoryModal`）を設置する。

### ⑨ 原本からの問題作成時の忠実性維持と先行設問答え漏洩（ネタバレ）の根絶
* **事象**:
  * 理科の大問1において、原本では「問4 図２の㋒と㋓のはたらきを簡単に説明しなさい。」となっていたが、アプリの問題文では「問1の組織㋒（師管）と組織㋓（道管）がそれぞれ果たしているはたらきを簡潔に説明しなさい。」と記述されていた。
  * このため、問1で問われている語句回答（㋒＝師管、㋓＝道管）が、問4の問題文を読むだけで生徒に丸わかり（ネタバレ・漏洩）になっていた。
* **原因**:
  * 単問（一問一答）演習用に「文脈がなくても解けるように」と問題作成者が親切心で補足括弧 `（師管）` `（道管）` を問題文に書き足してしまい、それを本番模試・大問一括の問題文（`final-challenge-pages.ts`）に流用した。
  * 原本テキストの文字起こし時に原本と完全一致させる確認プロセスが欠落していた。
  * 解答用紙側では答えの漏洩防止テストがあったが、問題用紙側で「先行する設問の正解語句が後続設問の問題文に含まれていないか」を検証するテストがなかった。
* **再発防止策**:
  * 原本が存在する問題は、**原本のテキスト・表記を勝手にアレンジ・肉付け・補足をせず完全忠実に文字起こし**すること。
  * 単一セクション内の設問間で、先行小問の解答となる重要語句（term）が後続設問の問題文（prompt）に括弧書き等で漏洩していないかを自動検査する単体テスト（`prompt-leakage.test.ts`）を常時維持する。

### ⑩ 問題用紙（出題形式）と解答用紙（入力スロット）の完全一致（型・小問・形式の整合性担保）
* **事象**:
  * 問題用紙では「問4: 図2の㋒と㋓のはたらきを簡単に説明しなさい。」という記述問題を出題しているにもかかわらず、解答用紙には「問4 [植物A] (選択): 選択肢 ア/イ/ウ/エ」「問4 [植物B] (選択): 選択肢 ア/イ/ウ/エ」と表示され、説明記述なのに無関係な選択肢の記入欄となっていた。
  * さらに問5（根毛の名称）の解答欄が消失し、問6（表面積の利点記述）が「問5 (記述)」にずれ込んでいた。
* **原因**:
  * 複数教科対応のコミット作業時に、`final-challenge-data.ts` 内の理科スロット定義が誤って別の一時的下書きデータで上書きされてしまい、問題用紙（`final-challenge-pages.ts`）との突合確認が行われないままマージされた。
  * テスト側も、本来22欄であるべきところを誤った23欄に合わせて `expect(sheetArea).toHaveTextContent('全 23 欄')` と安易にテストを書き換えて通してしまっていた。
  * 「問題用紙に書かれた各問（問4: 記述など）と、解答用紙のスロット（answerType, questionNumber, ラベル）が1対1に対応しているか」を検証する構造テストが存在しなかった。
* **再発防止策**:
  * 問題用紙の出題内容と、解答用紙のスロット（`answerType`, `questionNumber`, `partNumber`）は**必ず1対1で整合**させること。記述問題に対して選択欄を出したり、原本にない架空の小問（「植物A」「植物B」等）を表示することは厳禁。
  * 単体テスト（`prompt-leakage.test.ts`）において、問題用紙（`final-challenge-pages.ts`）と解答用紙（`final-challenge-data.ts`）の設問番号・設問タイプ・小問分割が完全一致しているかを自動検証する。
  * テストが落ちた際、データの異常を疑わずにテスト側のアサーション（例: 22欄→23欄）を安易に書き換えてパスさせないこと。

### ⑪ Stage 2（同等未見問題）における選択肢の提示保証と設問文内の答え漏洩（ネタバレ）防止
* **事象**:
  * Stage 2（同等未見問題）において、問題文が「(選択)」と指定され「記号で選びなさい」と問われているにもかかわらず、問題用紙（左ペイン）上に選択肢（ア〜エのテキスト）が一切表示されていなかった。
  * さらに設問文に「石灰石にうすい塩酸を加えたときに発生する気体（二酸化炭素）を選びなさい。」「都市名（函館）を選びなさい。」のように、正解そのものが括弧書きでネタバレ・漏洩していた。
* **原因**:
  * **UIレンダリングの欠落**: `FinalChallengePage.tsx` の Stage 2 描画処理で、`slot.stage2Prompt` のテキストのみを表示しており、`options` や `stage2Options` をレンダリングする UI コードが一行も実装されていなかった。
  * **データ定義の粗雑化**: Stage 2 スロットデータをAIが生成した際、出題者が「この設問は（二酸化炭素）を選ばせる問題」という内部メモ・正解ラベルを括弧書きのまま問題文（`stage2Prompt`）に残してしまった。
  * **選択肢の欠落**: 解答用紙側の `options: ['ア', 'イ', 'ウ', 'エ']` は「記号のみ」であり、問題用紙側にも選択肢文がないため、児童が何を基準に選べばよいか全く判別不能な状態になっていた。
* **再発防止策**:
  * **問題用紙UIでの選択肢カード描画**: `FinalChallengePage.tsx` の Stage 2 描画エリアで、`stage2Options` または `options` が存在する場合は必ず選択肢リストを視覚的なカードとして画面にレンダリングすること。
  * **問題文内の答えネタバレ撲滅**: `stage2Prompt` に答えの単語（`（二酸化炭素）` `（函館）` `（20℃以下）` 等）を括弧書き等で混入させない。
  * **自動テストによる完全ガード**: `prompt-leakage.test.ts` において、全教科の全 Stage 2 スロットに対し、①設問文に答えネタバレ括弧が存在しないこと、②選択問題（choice / multi_choice）の場合は必ず2件以上の具体的な選択肢テキスト（単なる1文字記号ではない）が定義されていることを自動検証する。

### ⑫ 合格のカギとカルテ学習の完全同期・認定試験段階報酬の分離
* **事象**:
  * 「合格のカギ」が認定試験側の右カラムに配置されていたため、カルテ内のテーマ（Lv.4マスター）とどう紐づいているかが直感的に分かりにくかった。
  * また、満点クリアの豪華報酬として「合格ドクター認定証」「金のマスター獣医師バッジ」「全動物たちからの特別感謝メッセージ」の3つが混在し、どの学習行動で何がアンロックされるのかの学習動線・目標設定が曖昧になっていた。
* **原因**:
  * カルテ学習（日々のテーマ習得）の達成目標と、認定試験（本番過去問および同等未見テスト突破）の達成目標がUI上で分離されておらず、ひとまとめに「認定試験の満点報酬」として抱え込まれていた。
* **再発防止策**:
  * **カギとカルテの完全結合**: 「合格のカギ」はカルテ領域（左カラム）に配置し、各テーマの【⭐Lv.4 マスター】達成でカギが手に入ることを明記。
  * **カルテ全制覇の特典**: カギをすべて集めると「🐾 全動物たちからの特別感謝メッセージ」モーダルがアンロックされる。
  * **認定試験の二段階クリア報酬**:
    * **Stage 1（過去問本番）クリア**: 👑「合格ドクター認定証（ライセンス）」授与＆画像保存
    * **Stage 1 & 2（同等未見問題）両方クリア**: ⭐「金のマスター獣医師バッジ」をアンロック
  * 認定証モーダル（`DoctorCertificateModal`）や過去の成績表モーダル（`FinalExamHistoryModal`）、試験終了画面（`FinalChallengePage`）において、両Stageの合格履歴（IndexedDB）を厳密に判定してバッジ授与を制御する。

### ⑬ PWAホーム画面追加時のアプリアイコン欠落（Android / iPadOS対応）
* **事象**:
  * Androidタブレットやスマートフォンで「ホーム画面に追加（PWAインストール）」した際、アプリアイコンが表示されず、ブラウザ標準の地球儀アイコンやイニシャル文字になっていた。
* **原因**:
  * `vite.config.ts` の manifest に `pwa-192x192.png` や `pwa-512x512.png` が宣言されていたが、`public/` フォルダ内に `favicon.svg` しか存在せず、実体のPNGアイコンファイルが欠落（404 Not Found）していた。
  * Android Chrome の WebAPK / PWA インストールでは、SVG形式ではなく PNG 形式（192x192, 512x512）および Android 8.0+ の適応型アイコン（`purpose: "maskable"`）が必須である。
* **再発防止策**:
  * `public/` 直下に、高品質な肉球アプリアイコン（`pwa-192x192.png`, `pwa-512x512.png`, `maskable-icon-512x512.png`, `apple-touch-icon.png`）を常時完備する。
  * `vite.config.ts` の manifest 設定で、通常アイコン（`purpose: "any"`）と適応型アイコン（`purpose: "maskable"`）を明示指定する。
  * `index.html` に `<link rel="apple-touch-icon" sizes="180x180" href="./apple-touch-icon.png" />` および `<meta name="theme-color" content="#2563EB" />` を記述する。

## 2. 実装チェックリスト（PR・コミット前確認）

- [ ] **UIと状態の結合**: クリック・操作した時に、対応する状態変更・永続化・フィードバック（音・紙吹雪・トグル）が正しく動作するか？
- [ ] **双方向性**: エクスポートを作ったら、インポート・復元も動作するか？
- [ ] **対象者配慮**: 用語は小学生向けになっているか？（高校理科用語や内部呼称の混入はないか？）
- [ ] **ルールの明確性**: カギやポイントなどのゲーム要素に、獲得条件と達成特典の説明があるか？
- [ ] **報酬体系と学習動線の整合**: カルテ学習（カギ獲得→全動物メッセージ）と認定試験（Stage 1: 認定証 / Stage 1&2: 獣医師バッジ）の段階報酬が仕様通り正しく連動・分離されているか？
- [ ] **原本忠実性・ネタバレ防止**: 問題文は原本通りに記載されているか？ 先行設問の答えが後続設問の問題文に漏洩していないか？
- [ ] **Stage 2 選択肢の提示とネタバレ防止**: Stage 2 の選択問題で問題用紙に選択肢（ア〜エの内容）が表示されているか？ 問題文に答えが括弧書きで漏洩していないか？
- [ ] **出題と解答欄の一致**: 問題用紙の設問内容・要求形式（記述・選択・語句）と、解答用紙の入力欄（slots）の小問・ラベル・answerTypeが1対1で完全一致しているか？
- [ ] **PWAアプリアイコン**: `public/` に 192x192, 512x512, maskable 512x512, apple-touch-icon の実体PNG画像が存在し、manifest に登録されているか？
- [ ] **タイムゾーン**: 日時・日付・タイムスタンプは日本時間（`Asia/Tokyo`）でフォーマットされているか？
- [ ] **条件分岐**: 存在しないリソースへの操作ボタンが画面に出ていないか？
- [ ] **自動テスト**: 単体・結合テスト（Vitest）を追加・実行し、全件パスしているか？
- [ ] **バージョン・タグ**: バージョン（`package.json`）とGitタグ（`vX.Y.Z`）が同期しているか？
