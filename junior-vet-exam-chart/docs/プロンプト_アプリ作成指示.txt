==================================================
0. 添付教材と作業環境
==================================================

教材の一次資料は次の6ファイルのみとする。

- rika-mondai.pdf   / rika-kaito.pdf    （理科）
- shakai-mondai.pdf / shakai-kaito.pdf  （社会）
- sansu-mondai.pdf  / sansu-kaito.pdf   （算数）

教材の性質：
- 問題PDFはページ画像のみで、文字データがない
- 解答PDFの文字データは文字化けしている箇所がある
- そのため、文字の読み取り（OCR）や抽出テキストは参考扱いとし、
  ページ画像を目で見て内容を確定させる
- 読めない箇所は推測で埋めず、needs_review として理由とともに残す
- 問題・枝問・選択肢・図・表・単位を省略しない
- 元問題にない事実を「過去問の内容」として追加しない

作業環境の条件：
- 実装するAIは、PDFのページ画像を目で見て読み取れる環境で作業する
- 読み取れない環境の場合は、作業を止めて報告する
- 文字の読み取り（OCR）の結果だけで設問のデータを作らない

進め方：
- 理科 → 社会 → 算数の順に、1教科ずつ進める（第29章）
- 理科でアプリ全体を最後まで完成させてから、
  社会・算数の教材を追加する

==================================================
1. 権利保護と配布方式（最優先）
==================================================

過去問の本文・画像・解答は第三者の著作物である。
公開リポジトリと公開GitHub Pagesには一切含めない。

配布を次の2つに分ける。

A. アプリ本体（公開リポジトリ・公開GitHub Pages）
   - プログラム、UI、フォント、サンプル教材のみ
   - サンプル教材は、本アプリ用に新規作成したオリジナル問題
     （理科・社会・算数それぞれ5問以上、10種類の問題形式をすべて含む）

B. 教材パック（非公開）
   - 過去問から作ったデータ、ページ画像、切り抜き画像
   - ローカルの content-private/ で作成する（Gitで管理しない）
   - アプリの「教材を読み込む」からzipファイルを選び、
     ブラウザ内のIndexedDBへ取り込む
   - 取り込み後はオフラインで利用できる

ビルド時の検査：
- 公開ビルドの成果物（dist）に、教材パック由来のファイル・文字列が
  含まれていたらビルドを失敗させる
- .gitignore で content-private/ を除外する

==================================================
2. 最上位目的
==================================================

元の過去問の答えを暗記させるアプリではない。

過去問から、出題者が要求する知識・理解・読解・判断・解法
（以下「Skill」）を逆算し、それを初見問題でも再現できる
状態まで鍛える。

最終到達状態：
1. 元の過去問を本番形式で満点
2. Skill構成と難易度が同等の未見問題でも満点
3. 時間を空けても再現できる
4. 選択肢に頼らず自力で思い出せる
5. 算数は答えではなく、解法と次の一手を判断できる

学習の単位は「問題」ではなく「Skill」とする。

学習の流れ：
過去問の分析 → 初期診断 → Skill別学習 → 想起 →
理由・解法の確認 → 初見への転用 → 時間差復習 →
複数Skillの統合 → 元の過去問 → 同等の未見問題

==================================================
3. UXの原則
==================================================

対象：小学生がiPad／Androidタブレットで使う。

回答操作はこれだけに限定する：
タップ、選択、ドラッグ（タップでの代替あり）、
図上の位置指定、数字入力、紙で解いた後の自己判定

禁止：
- 文章の入力を求めること（どの画面でも）
- 1画面に複数の問題を出すこと
- 学習する問題を子どもに毎回選ばせること
- 最初から長い解説を全文表示すること
- 不要な確認ダイアログ
- ランキング、他人との比較
- 学習を邪魔する演出や連続アニメーション

==================================================
4. 習得モデル
==================================================

Skillごとに次の7段階で管理する。

| 段階 | 表示名 | 到達条件 |
|---|---|---|
| M0 | 未学習 | 初期状態 |
| M1 | 見れば分かる | 選択肢を見て正解 |
| M2 | 思い出せる | 選択肢を見る前に正しく想起（異なる問題2問以上） |
| M3 | 使い方が分かる | Why Choice または Next Step で正解（2問以上） |
| M4 | 初見に使える | 判定に使える転用問題（第8章）で、ヒントなし正解（2問以上、題材が異なること） |
| M5 | 定着 | M4到達から24時間以上空けた復習で正解し、さらに72時間以上空けた復習でも正解 |
| M6 | Master | 本番形式（Final Challenge）で、そのSkillを含む設問に正解 |

共通ルール：
- 同じ問題の繰り返し正解では M2 を超えない
- 同じ選択肢の並び順での正解は M2 の判定に使わない
- 転用問題に正解するまで「理解済み」と表示しない
- 「Master」と表示するのは M6 だけ
- 下の段階の問題を間違えた場合は1段階下げる
  （M5・M6 は M4 まで下げる）

masteryScore（0〜100）も内部で持つ。
- 基本点：M0=0, M1=15, M2=35, M3=55, M4=75, M5=90, M6=100
- 次の段階の条件を一部満たしている場合は、達成した割合に応じて
  次の段階の基本点との差を加算する
- ヒント使用、回答時間が目安の3倍超、自己判定のみの正解は、
  加算を半分にする
- 計算は src/domain/mastery.ts の純粋関数に実装し、
  単体テストで全遷移を確認する

用語の定義：
- 主要Skill：元過去問の配点対象になっている設問に紐づく全Skill
- 中核Skill：元過去問の2問以上に紐づくSkill、または算数の解法Skill

==================================================
5. Recall First（まず思い出させる）
==================================================

選択式の問題でも、最初は選択肢を隠して問題だけを見せる。

待ち時間の自動調整（初期値）：
- 新しいSkill：8秒 / 学習中：6秒 / 定着確認：4秒
- 算数の文章題・図形：10秒
- 直近3回の想起成功率が80%以上なら2秒短縮（最短3秒）

設定で選べる値：0 / 3 / 5 / 8 / 10秒 / 自動（初期値は自動）

待っている間のボタン：
- 「分かった」→ 答えを見せ、自己判定
  （合っていた / 惜しかった / 分からなかった）
- 「選択肢を見る」→ すぐに選択肢を表示

評価の高い順：
選択肢を見ずに想起 > 選択肢を見て正解 > ヒント後に正解 > 答えを見て確認

自己判定で「合っていた」を選んだ場合は、すぐ後に同じSkillの
選択問題を1問出して確かめる（自己判定の誤りを防ぐため）。

カウントダウンは小さく表示し、焦らせない。

==================================================
6. 問題形式（10種類すべて実装）
==================================================

1. Recall Card：用語・人物・図を見て「分かった/分からない」→答え→自己判定
2. Delayed Choice：問題だけ表示→待ち時間後に2〜4択
3. Multiple Choice：普通の2〜4択（本番の再現や誤解の見分けに使う）
4. Why Choice：正解後に理由を2〜4択で選ぶ。
   毎回は出さず、M2→M3の判定時、偶然の正解が疑われる時、
   理科の因果関係、社会の原因と結果、算数の根拠確認で出す
5. Next Step：「次に何をする？」を選ぶ（主に算数）
   着眼点 → 解法 → 最初の一手 → 途中の一手 → 式 → 計算 → 検算
6. Ordering：カードを並べ替える。タップで順番を指定する代替操作も必須
7. Diagram Touch：地図・グラフ・図・図形をタップ。
   判定範囲は、画像の幅と高さを1としたときの比率座標の多角形で保存する。
   拡大しても判定がずれないこと
8. Matching：左の項目をタップ→右の項目をタップで対応づけ
9. Numeric Answer：数字キーパッド（0-9、小数点、分数、比、負号）と
   単位の選択。文字キーボードは出さない
10. Self Check：紙で解いた後に
    「正解した / 解き方は合っていたが計算ミス / 途中まで分かった /
    解き方が分からなかった」を選ぶ。
    自己判定だけでは M3 以上にしない

元問題が文章で答える形式の場合、文章入力ではなく次に置き換える：
- 必要な要素を複数選ぶ
- 原因→結果を並べ替える
- 正しい説明文を選ぶ
- 足りない要素を選ぶ
- 間違っている部分をタップする

ヒント：
- すべての練習問題・転用問題に、ヒントを2段階用意する
  1段階目：どこに注目するか
  2段階目：何を使うか（答えそのものは書かない）

==================================================
7. 教科別の設計
==================================================

理科：
用語、原理、因果関係、実験手順、図・表・グラフの読み取り、
条件比較、計算、理由の判断、別の現象への応用。
転用問題では、生物・装置・現象・数値を変えて同じ原理を問う。

社会：
人物、地名、用語、制度、年代、出来事、原因と結果、
地図、表・グラフ・史料、複数資料のつなぎ合わせ。
次の両方向で確認する：
人物⇔出来事、出来事⇔時代、出来事⇔原因・結果、
地名⇔地図、資料⇔結論。

算数：
答えの暗記は学習成果に数えない。
各問題を、必要な知識 / 問題タイプ / 着眼点 / 必要な情報 /
不要な情報 / 最初の一手 / 解法 / 式 / 計算 / 検算 /
よくある間違い、に分解する。
学習順：原理 → タイプ認識 → 着眼点 → 解法選択 → 最初の一手 →
途中式 → 数字を変えた問題 → 題材を変えた問題 →
紙で全体を解く → 時間差復習 → 本番問題。
誤答選択肢には、ランダムな数値ではなく
「よくある間違った解き方」から出る値を使う。

==================================================
8. 転用問題（初見でも使えるかの確認）
==================================================

作成数：
- 中核Skill：3問以上
- その他の主要Skill：2問以上

作り方：
問題文・題材・数値・図・資料・問い方・選択肢・順番のうち
3項目以上を変え、必要なSkillは同じにする。

禁止：
- 固有名詞や数字だけを入れ替えた問題
- 元問題と同じ選択肢の並び
- 元問題特有の言葉だけで正解できる問題

各転用問題に必ず保存する項目：
sourceQuestionIds, requiredSkillIds, changedAspects,
expectedReasoning, correctAnswer, distractorRationale,
hints, validationStatus

validationStatus：
- draft：AIが作成しただけ。学習には出すが、習得判定に使わない
- self_verified：AIが別の解き方で解き直し、正解と一致。
  M4・M5 の判定に使える
- human_verified：保護者などが確認画面で承認。
  すべての判定に使える

人による確認が必要なのは、Final Challenge Stage 2（第13章）で
使う問題だけとする。それ以外は self_verified で運用する。

アプリ内に「この問題はおかしい」ボタンを置き、
押された問題は draft に戻す。

==================================================
9. 誤答の分析
==================================================

誤答の原因の分類：
知識不足 / 用語の混同 / 原理の未理解 / 因果の逆転 /
条件の読み落とし / 図の読み違い / 表・グラフの読み違い /
時代の混同 / 問題タイプが分からない / 着眼点が分からない /
解法を選べない / 式を立てられない / 計算ミス / 単位ミス /
選択肢の読み違い / 偶然の正解 / 時間切れ

1問の誤答だけで原因を決めない。
関連する確認問題を1〜2問出して原因を絞り込む。

誤答後の流れ：
着眼点の確認 → 用語・原理の確認 → 次の一手の確認 →
短い解説（3行以内）→ やさしい確認問題 → 転用問題

==================================================
10. 時間差復習
==================================================

次回の復習日時の決め方：
- 段階：10分後 / 1日後 / 3日後 / 7日後 / 16日後 / 35日後
- 選択肢を見ずに即答した場合：1段階先へ進める
- 選択肢を見て正解した場合：同じ段階をもう一度
- 誤答した場合：最初の段階に戻す
- 過去に忘れた回数が2回以上なら、間隔を0.7倍にする

端末の時計が過去に戻っても復習予定が壊れないこと
（最後に記録した時刻より前の時刻は無視する）。

現在時刻は src/domain/clock.ts からのみ取得する。

==================================================
11. 毎日の学習
==================================================

アプリが毎日の問題を自動で決める。

標準の10問の内訳（初期値）：
忘れかけ3 / 前回の誤答2 / 新しいSkill2 / 転用問題2 / 統合問題1

足りない区分の分は、忘れかけ → 誤答 → 新しいSkill の順で補う。
問題数は 5 / 10 / 15 から設定で選べる。

開始前に、問題数・目安時間・主な分野だけを表示する。
学習中は1問ずつ表示する。

==================================================
12. 初期診断と統合問題
==================================================

初期診断：
- 教材パックを最初に読み込んだ後、1回だけ実施する
- 中核Skillごとに1問、Delayed Choice または Next Step で出す
- 最大30問、所要時間の目安は20分
- 途中でやめても続きから再開できる
- 正解したSkillは M1、選択肢を見ずに正解したSkillは M2 から始める
- 診断で間違えたSkillを、毎日の学習で優先して出す

統合問題：
- 2つ以上の中核Skillを使わないと解けない問題
- 元過去問の大問1つ分の構成を短くしたもの
- 対象のSkillがすべて M3 以上になってから出す

==================================================
13. Final Challenge（最終試験）
==================================================

Stage 1：元の過去問
- 元のページ画像をそのまま表示し、拡大できる
- 解説・ヒント・思い出す待ち時間なし
- 制限時間は、問題PDFの表紙に書かれた試験時間を使う
- 回答欄は画面の右に、元の設問番号順に表示する
- 算数は紙やノートとの併用を認める

答えが1つに決まらない記述問題（answerType = open）：
- 模範解答から「採点で必要な要素」を2〜4個書き出しておく
- 学習中は「必要な要素を選ぶ」「正しい説明を選ぶ」で確認する
- Stage 1 では、紙に書いた後で模範解答と必要な要素を表示し、
  要素ごとに「書けた／書けなかった」を選ばせる
- すべての要素が「書けた」の場合のみ正解とする
- 結果画面に、自己判定による採点であることを表示する

Stage 2：同等の未見問題
- 元過去問と同じ問題数・同じSkill構成・同じ配点・同程度の難易度で
  1セット作る
- 問題文・数値・図・資料・題材は変える
- このセットの問題はすべて human_verified にする

確認画面（人による確認）：
- 1問30秒以内で確認できるように、問題・答え・考え方・元の設問を
  1画面に並べる
- 承認 / 差し戻し / コメントを記録する
- 確認の進み具合（例：12 / 40）を表示する

解放条件：主要Skillがすべて M4 以上、中核Skillがすべて M5 以上
Master判定：Stage 1 と Stage 2 がともに満点
合格点は config/thresholds.json で変えられること（開発・テスト用）

==================================================
14. 教材パックの作成方法
==================================================

14.1 基本方針
- 教材パックは開発時に作成する。アプリの使用中にAIやOCRは使わない
- PDFの読み取り、設問のデータ化、Skillへの分解、類題の作成は、
  実装するAIが開発環境で行い、すべてファイルとして残す
- 人による確認が必要な箇所では、必ず作業を止める
- 教科ごとに作成する（--subject rika / shakai / sansu）

14.2 使う道具（固定）
- スクリプトはTypeScriptで書き、tsxで実行する
- PDFを画像にする：pdfjs-dist と @napi-rs/canvas
  （OSに別のソフトを入れなくても動くようにする）
- 画像の切り抜き・変換：sharp
- 圧縮：JSZip
- データの検証：zod（アプリと同じ型定義を共有する）

14.3 作業用フォルダの構成（Gitで管理しない）
content-private/
  source-pdf/                    元の6つのPDF
  pages/<subject>/p001.png ...   ページ画像（200dpi）
  inventory/<subject>.csv        回答欄の一覧（全問題の基準一覧）
  inventory/<subject>-review.html
  approvals/                     人が承認した記録
  authoring/<subject>/
    questions.json   設問（問題文、選択肢、答え、ページ番号）
    figures.json     図表の切り抜き範囲
    skills.json      Skillとその関係
    practice.json    練習問題
    transfer.json    転用問題
    integrated.json  統合問題
    stage2.json      Final Challenge Stage 2 の問題
    regions.json     タップ判定の範囲
  build/            途中で作るファイル
  dist-pack/        できあがった教材パック（zip）

14.4 回答欄の一覧（inventory）の列
subject, page, section, question, part, answerSlotLabel,
answerText, answerType, status, note

answerType：choice / multi_choice / term / numeric / order / open
status：ok / needs_review

14.5 コマンドと手順
1. npm run pack:pages -- --subject <subject>
   PDFの全ページを200dpiのPNGにし、ページ数を pages-index.json に記録
2. npm run pack:inventory -- --subject <subject>
   解答PDFのページ画像を見て、回答欄を1つずつ inventory に書く
   （AIが画像を見て作業し、スクリプトは書式を確認する）
3. npm run pack:review -- --subject <subject>
   ページ画像に設問番号を重ねた確認用ページを作る
   → 【停止】人が確認し、approvals/<subject>-inventory.json に
     承認を記録する。承認されるまで次へ進まない
4. 設問のデータ化（questions.json、figures.json）
   questionId の形式：<subject>-<年度>-<大問2桁>-<小問2桁>[-<枝問>]
   例：rika-2024-01-01、shakai-2024-02-08-c
   答えは2つの方法で確かめる：
     A：解答PDFの画像から読み取る
     B：問題を実際に解いて答えを出す
   AとBが一致しない場合は needs_review とし、理由を書く。
   算数は必ず解いて確かめる。理科・社会の知識問題は、
   解答PDFの読み取りを2回別々に行って比べる
5. npm run pack:crop -- --subject <subject>
   figures.json の範囲（比率座標）で図表を切り抜き、
   WebP（長い辺が最大1600px）にする。範囲は範囲エディタ（第16章）で指定する
6. Skill・練習問題・転用問題・統合問題・Stage 2 問題の作成。
   作成直後の状態は draft とする
7. npm run pack:verify -- --subject <subject>
   転用問題などをAIが別の解き方で解き直す。一致すれば self_verified
   → 【停止】Stage 2 の問題を人が確認画面で承認し、human_verified にする
8. npm run pack:check -- --subject <subject>
   カバレッジ検査（第15章）。エラーが1件でもあれば失敗する
9. npm run pack:build
   承認済みの教科をまとめて教材パックのzipを作る

14.6 教材パックの中身
master100-pack-<examId>-<contentVersion>.zip
  manifest.json
  data/questions.json, answers.json, figures.json, skills.json,
       skill-dependencies.json, practice.json, transfer.json,
       integrated.json, stage2.json, regions.json, exams.json
  images/pages/<subject>/p001.webp ...
  images/figures/<figureId>.webp

manifest.json の項目：
- packId、examId（例：yasuda-2024）
- schemaVersion（データ形式の版。アプリと合わない場合は読み込まない）
- contentVersion（教材の版。修正のたびに上げる）
- createdAt
- 収録教科と、教科ごとの試験時間・ページ数・設問数
- 全ファイルの一覧と SHA-256 の値
- needs_review の件数

14.7 アプリへの読み込み
- 設定画面の「教材を読み込む」からzipを選ぶ
- 確認する内容：zipの形式、SHA-256の値、データ形式の版、
  zodによる検証、ファイルの大きさの上限（200MB）
- 問題があれば読み込まず、どのファイルのどこがおかしいかを表示する
- 同じ examId の新しい版を読み込んだ場合、questionId と skillId が
  同じものの学習履歴を引き継ぐ。消えた設問の履歴は残し、使わないだけにする
- 教科を追加した新しい版（例：理科のみ → 理科＋社会）を読み込んでも、
  既存の教科の学習履歴を引き継ぐ
- 複数の学校・年度のパックを同時に読み込める

14.8 別の学校・年度を追加する手順
README に、14.5 の手順を新しいPDFで繰り返す方法を書く。
examId を変えれば、既存のパックや学習履歴に影響しないこと。

15. カバレッジの検証
==================================================

スクリプト：scripts/coverage-check.ts（教科ごとに実行できる）

確認する項目：
- inventory の全行に questionId が1対1で対応している
- 問題PDFの全ページが、1つ以上の questionId から参照されている
- questionId の重複・欠番がない
- すべての questionId に答えがある
  （needs_review の場合は理由がある）
- open の設問に、採点で必要な要素が2〜4個ある
- すべての questionId に Skill が1つ以上ある
- すべての主要Skillに、練習問題と、第8章の規定数以上の転用問題がある
- すべての練習問題・転用問題に、2段階のヒントがある
- Stage 2 のセットが元過去問と同じ問題数で、すべて human_verified
- 図表の参照切れがない
- すべての Diagram Touch に判定範囲がある

出力：coverage-report.json / coverage-report.html
（教科、ページ、設問番号、各状態、備考を一覧表示し、
各行から元のページ画像を開ける）

エラーが1件でもあれば教材パックの作成を失敗させる。
needs_review の件数は必ず報告する。

29. 進め方と区切り
==================================================

教科の順番：理科 → 社会 → 算数

【第1段階：理科でアプリ全体を完成させる】
区切りごとに合格条件を自分で確認し、結果を報告してから次へ進む。

K1：理科の 14.5 手順1〜3（ページ画像と回答欄の一覧）
    → 【停止】人の承認を待つ
K2：理科の 14.5 手順4〜8（全問のデータ化、カバレッジのエラー0件）
K3：土台（デザイントークン、フォント、画面の骨組み、画面配置テスト）
K4：10種類の問題形式と部品のテスト（サンプル教材を使用）
K5：習得の判定、復習、毎日の学習、初期診断（単体テスト）
K6：理科の Skill、練習問題、転用問題、統合問題、Stage 2 問題と確認画面
    → 【停止】Stage 2 の問題の人による確認を待つ
K7：Final Challenge、結果、設定、保存、教材パックの読み込み
K8：画面の流れのテスト、画像比較（→【停止】基準画像の承認）、
    アクセシビリティ
K9：GitHub Pages の公開、README、理科の段階の報告

第1段階の完了条件：
第28章のうち、社会・算数に関する項目を除くすべてを満たすこと。
→ 【停止】報告し、承認を得てから第2段階へ進む

【第2段階：社会を追加する】
- 社会について K1 → K2 → K6 を行う（各停止点を含む）
- 地図・資料・年代など、理科になかった問題形式の使い方で
  不具合や不足が見つかった場合は、アプリ本体を直し、
  その箇所のテストを追加する
- 理科の学習履歴を引き継いだまま、理科＋社会の教材パックを読み込めること
- 第28章の社会に関する項目と、全テストの成功を確認して報告する
→ 【停止】承認を得てから第3段階へ進む

【第3段階：算数を追加する】
- 算数について K1 → K2 → K6 を行う（各停止点を含む）
- Next Step、図形、補助線、紙で解いた後の自己判定を重点的に確認する
- 第28章のすべての項目を確認し、最終報告（第31章）を行う

共通：
- 一部の教科や設問だけを入れた状態で「完成」と報告しない
- 前の段階で合格したテストが、後の段階で失敗しないこと
